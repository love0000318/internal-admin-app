# 휴가 Import 운영 리허설 Runbook

## 목적

휴가 사용내역 엑셀 import를 실제 운영에 반영하기 전에 OWNER가 따라야 할 리허설 절차입니다. 목표는 업로드, 파싱, 미리보기, 검증, Step-up, 최종 반영, 반영 후 정합성 확인까지 안전하게 점검하는 것입니다.

실제 개인정보가 포함된 엑셀 원본은 GitHub, public 폴더, 문서에 저장하지 않습니다.

## 업로드 전 준비

- 운영 URL과 로그인 계정이 OWNER인지 확인합니다.
- 업로드 파일이 최신본인지 확인합니다.
- 파일 확장자가 `.xlsx`인지 확인합니다.
- 월별 파일과 상세 파일을 혼동하지 않도록 파일명을 확인합니다.
- 실제 업로드 전 테스트 직원 또는 제한된 직원 범위로 preview 리허설을 먼저 진행합니다.
- 최종 반영 담당자는 Step-up 재인증에 사용할 본인 비밀번호를 준비합니다.

## 지원 파일 형식

### 월별 연차 사용 내역

필수 컬럼:

- 이름
- 사번
- 입사일
- 잔여 연차
- 1월 ~ 12월

확인 목적:

- 직원 매칭
- 입사일 파싱
- 잔여 연차 숫자 파싱
- 월별 사용량 파싱
- 엑셀 잔여와 시스템 잔여 차이 계산

### 휴가 사용 상세 내역

필수 컬럼:

- 사번
- 이름
- 회사내이름
- 조직
- 휴가 시작일
- 휴가 종료일
- 항목
- 사용시간(일)
- 사용시간(시간)
- 상태
- 증명자료

확인 목적:

- header row 자동 탐색
- Excel serial date와 문자열 날짜 변환
- 직원 매칭
- 휴가 유형 매핑
- 상태 매핑
- UNKNOWN, 취소, 승인대기, 중복 의심 row 분리

## 월별 연차 사용 내역 리허설

1. OWNER로 로그인합니다.
2. `/admin/leaves/import`로 이동합니다.
3. 업로드 유형을 `월별 연차 사용 내역` 또는 자동 감지로 선택합니다.
4. `.xlsx` 파일을 업로드합니다.
5. batch 상세 화면에서 rowCount, matched, unmatched, warning, error 수를 확인합니다.
6. 직원 미매칭 row가 있으면 수동 매칭하거나 원본 파일을 수정해 다시 업로드합니다.
7. 엑셀 잔여 연차와 시스템 잔여 연차 차이를 확인합니다.
8. 차이가 0인 row는 조정 대상이 아닌지 확인합니다.
9. 차이가 있는 row만 ADJUSTED 반영 예정으로 표시되는지 확인합니다.
10. Step-up 없이 반영을 시도하면 실패해야 합니다.
11. Step-up 후 최종 반영합니다.
12. 직원별 휴가 현황과 batch reconciliation을 확인합니다.
13. 같은 batch 재반영이 차단되는지 확인합니다.
14. AuditLog에 import 관련 이벤트가 남았는지 확인합니다.

## 휴가 사용 상세 내역 리허설

1. OWNER로 로그인합니다.
2. `/admin/leaves/import`로 이동합니다.
3. 업로드 유형을 `휴가 사용 상세 내역` 또는 자동 감지로 선택합니다.
4. `.xlsx` 파일을 업로드합니다.
5. 안내문 row 뒤에 있는 header가 정상 감지되었는지 확인합니다.
6. 휴가 시작일과 종료일이 올바른 날짜로 변환되었는지 확인합니다.
7. 직원 매칭 결과를 확인합니다.
8. 휴가 유형 매핑 결과를 확인합니다.
9. 상태 매핑 결과를 확인합니다.
10. UNKNOWN row가 반영 불가로 표시되는지 확인합니다.
11. 휴가취소 row가 사용량 차감 대상에서 제외되는지 확인합니다.
12. 승인대기 row가 pending으로만 반영 예정인지 확인합니다.
13. 승인완료 row만 used로 반영 예정인지 확인합니다.
14. 중복 의심 row가 경고 또는 skip 대상으로 표시되는지 확인합니다.
15. Step-up 없이 반영을 시도하면 실패해야 합니다.
16. Step-up 후 최종 반영합니다.
17. 생성된 LeaveRequest, LeaveLedger 수를 확인합니다.
18. 같은 batch 재반영이 차단되는지 확인합니다.
19. AuditLog에 import 관련 이벤트가 남았는지 확인합니다.

## 미매칭 row 처리

- 사번이 시스템의 직원 사번과 일치하는지 확인합니다.
- 회사내이름, 이름, 조직명이 시스템과 다르면 원본 파일 또는 직원 프로필을 보정합니다.
- 미리보기에서 수동 매칭할 수 있는 경우 해당 row에 사용자를 지정합니다.
- 미매칭 row는 최종 반영할 수 없습니다.

## 휴가 유형 매핑 처리

- raw 항목이 시스템 휴가 유형 코드로 매핑되었는지 확인합니다.
- 시스템에 없는 휴가 유형은 자동 생성하지 않습니다.
- 필요한 휴가 유형을 먼저 생성하거나 row 매핑을 보정한 뒤 반영합니다.

## UNKNOWN 상태 처리

- 상태가 공란이거나 판단 불가인 row는 `UNKNOWN`으로 표시됩니다.
- UNKNOWN row는 자동 반영되지 않습니다.
- 운영자가 원본 파일 상태를 확인해 승인대기, 승인완료, 취소 중 하나로 보정해야 합니다.

## 중복 의심 row 처리

- 동일 직원, 동일 기간, 동일 휴가 유형, 동일 수량의 기존 휴가 요청이 있으면 중복 의심으로 표시됩니다.
- 중복 의심 row는 기본적으로 skip 또는 확인 필요 상태로 처리합니다.
- 실제 중복이 아니면 원본 기간, 수량, 유형을 재확인한 뒤 별도 운영 판단으로 처리합니다.

## 최종 반영 전 확인

- 반영 예정 직원 수
- 생성될 LeaveRequest 수
- 생성될 LeaveLedger 수
- 생성될 LeaveAdjustment 수
- 반영 제외 row 수
- 오류 row 수
- 경고 row 수
- UNKNOWN row 수
- 중복 의심 row 수

## 반영 후 확인

- batch 상태가 `APPLIED`인지 확인합니다.
- row별 applied 상태와 생성된 ID를 확인합니다.
- 직원별 휴가 현황에서 잔여 연차를 확인합니다.
- 월별 파일은 엑셀 잔여와 시스템 잔여 차이가 0인지 확인합니다.
- 상세 파일은 취소 row가 used로 차감되지 않았는지 확인합니다.
- AuditLog에서 `LEAVE_IMPORT_APPLY_COMPLETED`를 확인합니다.

## 문제가 있을 때

- batch 재반영은 시도하지 않습니다.
- 생성된 LeaveRequest, LeaveLedger, LeaveAdjustment ID를 batch 상세에서 확인합니다.
- 자동 rollback은 기본 지원하지 않으므로 운영 담당자가 batch 기준으로 수동 보정합니다.
- 대량 오류가 있으면 실제 반영 전 파일을 수정해 새 batch로 다시 업로드합니다.

## 금지 사항

- 운영 DB에서 `migrate reset` 사용 금지
- 실제 개인정보 엑셀 파일 GitHub 업로드 금지
- 엑셀 원본 public 저장 금지
- UNKNOWN row 자동 승인 처리 금지
- 취소 row 사용량 차감 금지
- OWNER 외 사용자 import 접근 허용 금지
- Step-up 없는 최종 반영 금지
