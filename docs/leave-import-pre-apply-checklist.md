# 휴가 Import 최종 반영 전 체크리스트

## 공통

- [ ] 업로드 파일이 최신본인지 확인했다.
- [ ] 파일 확장자가 `.xlsx`인지 확인했다.
- [ ] 실제 개인정보 파일을 GitHub나 public 폴더에 저장하지 않았다.
- [ ] 업로드한 batch의 파일 유형이 올바르게 감지되었다.
- [ ] 전체 row 수가 원본 파일 예상 row 수와 맞다.
- [ ] 오류 row 수를 확인했다.
- [ ] 경고 row 수를 확인했다.
- [ ] 반영 제외 row 수를 확인했다.
- [ ] 반영 예정 row 수를 확인했다.
- [ ] 최종 반영 담당자가 OWNER 계정인지 확인했다.
- [ ] Step-up 재인증 준비가 되어 있다.

## 직원 매칭

- [ ] 미매칭 row가 없다.
- [ ] 중복 매칭 row가 없다.
- [ ] 사번이 시스템 직원 정보와 일치한다.
- [ ] 회사내이름 또는 이름이 시스템 직원 정보와 일치한다.
- [ ] 조직명이 다른 row는 원인을 확인했다.
- [ ] 수동 매칭한 row는 다시 검증했다.

## 월별 연차 사용 내역

- [ ] 필수 컬럼이 모두 있다: 이름, 사번, 입사일, 잔여 연차, 1월~12월.
- [ ] 입사일이 정상 파싱되었다.
- [ ] 잔여 연차가 숫자로 정상 파싱되었다.
- [ ] 월별 사용량이 숫자로 정상 파싱되었다.
- [ ] 엑셀 잔여와 시스템 잔여 차이를 확인했다.
- [ ] 차이가 0인 row가 조정 대상에서 제외되는지 확인했다.
- [ ] 차이가 있는 row만 LeaveAdjustment 또는 LeaveLedger ADJUSTED 예정인지 확인했다.
- [ ] 반영 후 reconciliation에서 차이를 다시 확인할 계획이 있다.

## 휴가 사용 상세 내역

- [ ] 필수 컬럼이 모두 있다: 사번, 이름, 회사내이름, 조직, 휴가 시작일, 휴가 종료일, 항목, 사용시간(일), 사용시간(시간), 상태, 증명자료.
- [ ] header row가 정상 감지되었다.
- [ ] Excel serial date가 올바른 날짜로 변환되었다.
- [ ] 문자열 날짜가 올바른 날짜로 변환되었다.
- [ ] 시작일이 종료일보다 늦은 row가 없다.
- [ ] 사용시간(일)이 0 이하인 row가 없다.
- [ ] 휴가 유형 미매핑 row가 없다.
- [ ] UNKNOWN 상태 row가 없다.
- [ ] 중복 의심 row를 확인했다.
- [ ] 휴가취소 row가 사용량으로 반영되지 않는지 확인했다.
- [ ] 승인대기 row가 pending으로만 반영되는지 확인했다.
- [ ] 승인완료 row만 used로 반영되는지 확인했다.

## 보안과 감사

- [ ] OWNER 외 사용자로 접근이 차단되는지 확인했다.
- [ ] Step-up 없이 최종 반영이 실패하는지 확인했다.
- [ ] AuditLog에 엑셀 row 원문 전체가 저장되지 않는지 확인했다.
- [ ] AuditLog에 주민등록번호, 계좌번호, token, secret이 저장되지 않는지 확인했다.
- [ ] 업로드 파일 원본이 public에 저장되지 않는지 확인했다.

## 최종 반영 후 확인

- [ ] batch 상태가 APPLIED로 변경되었다.
- [ ] 같은 batch 재반영이 차단된다.
- [ ] row별 applied 상태가 기록되었다.
- [ ] 생성된 LeaveRequest ID를 확인했다.
- [ ] 생성된 LeaveLedger ID를 확인했다.
- [ ] 생성된 LeaveAdjustment ID를 확인했다.
- [ ] 직원별 휴가 현황에 반영되었다.
- [ ] `/leaves/me`의 잔여와 관리자 휴가 현황의 잔여가 일치한다.
- [ ] AuditLog에 `LEAVE_IMPORT_APPLY_COMPLETED`가 기록되었다.
