# 직원 오픈 이슈 대응 가이드

직원 오픈 중 자주 발생할 수 있는 문제와 확인 절차를 정리한다. 실제 secret, token, 가입 인증 코드, DB URL은 문서에 기록하지 않는다.

## 초대 링크가 만료되었다고 나오는 경우

확인:

- 직원이 최신 초대 링크를 사용했는지
- 가입 인증 코드도 최신인지
- 초대가 이미 사용되었는지
- 초대가 만료되었는지
- 초대가 취소 또는 재발급되어 이전 링크가 폐기되었는지
- production `APP_BASE_URL`이 올바른지

조치:

1. OWNER가 초대 상태를 확인한다.
2. 기존 초대가 만료/사용/폐기 상태이면 초대를 재발급한다.
3. 새 단축 초대 URL과 새 가입 인증 코드를 직원에게 전달한다.
4. 이전 링크와 코드는 사용하지 말라고 안내한다.

## 가입 인증 코드가 틀리다고 나오는 경우

확인:

- 코드 오타
- 대소문자 혼동, 영문 코드 사용 시
- 이미 사용된 코드
- 만료된 코드
- 재발급 전 이전 코드 사용 여부
- 실패 횟수 초과 여부

조치:

1. 직원에게 코드를 다시 입력하게 한다.
2. 계속 실패하면 OWNER가 초대를 재발급한다.
3. 새 코드 전달 후 이전 코드는 폐기되었다고 안내한다.

## 직원이 로그인되지 않는 경우

확인:

- 전화번호 입력 형식
- 비밀번호 오타
- 계정 status가 ACTIVE인지
- 최근 가입이 완료되었는지
- 세션/cookie 오류 가능성
- 최근 배포 오류
- 로그인 실패 제한에 걸렸는지

조치:

- 잠시 후 다시 시도하도록 안내한다.
- 계정 상태를 OWNER가 확인한다.
- 비밀번호 재설정 기능이 없으면 관리자 지원 절차를 안내한다.
- 필요 시 계정을 비활성화하고 재초대한다.

## 휴가 요청이 안 되는 경우

확인:

- 휴가 잔여 수량
- 휴가 유형 활성화 여부
- 사용 가능 기간
- 요청 날짜가 회사 휴일/주말인지
- 기존 휴가와 중복되는지
- 승인 정책
- 증명자료 필요 여부
- 생일 반차/맞춤휴가 grant가 실제로 남아 있는지

조치:

- 잔여나 grant가 없으면 직원에게 안내한다.
- 휴가 유형 설정을 OWNER가 확인한다.
- 증명자료가 필요한 경우 제출 상태를 확인한다.
- 중복 요청이면 기존 요청 상태를 확인하게 한다.

## 출근/퇴근이 안 되는 경우

근태 기능을 운영 범위에 포함한 경우:

확인:

- 오늘이 근무일인지
- 회사 휴일인지
- 이미 출근했는지
- 이미 퇴근했는지
- 계정 상태가 ACTIVE인지
- 근태 정책이 적용되어 있는지
- `/attendance` route가 production에서 정상인지

조치:

- 중복 출근/퇴근이면 현재 기록을 확인한다.
- 퇴근 누락은 근태 수정 요청 절차를 안내한다.
- route가 404이면 근태 기능이 이번 릴리즈에서 제외된 상태인지 확인한다.

## 모바일 화면이 깨져 보이는 경우

확인:

- 기기명
- OS/브라우저 버전
- 화면 폭
- 깨진 화면 URL
- screenshot
- 최근 배포 여부

조치:

- 브라우저 새로고침과 캐시 삭제를 안내한다.
- 같은 문제가 여러 직원에게 반복되면 P1 또는 P0로 분류한다.
- 핵심 기능 사용 불가이면 직원 오픈을 일시 중단한다.

## 알림이 안 보이는 경우

확인:

- 알림센터 접근 가능 여부
- 읽지 않은 알림 badge 표시 여부
- 해당 이벤트가 실제로 발생했는지
- 내부 Notification 생성 여부
- 외부 이메일/Slack은 사용 설정되어 있는지

조치:

- 내부 알림센터를 우선 확인하게 한다.
- 외부 알림이 비활성인 경우 운영 정책을 안내한다.

## 보안 사고 의심 시

확인:

- 의심 계정
- 최근 로그인 이벤트
- 권한 변경 이벤트
- 초대 재발급 이벤트
- CSV/AuditLog export 이벤트
- Vercel/Neon/GitHub 접근권한 변경

조치:

1. 의심 사용자 session revoke
2. OWNER 비밀번호 변경
3. 필요한 경우 secret rotation
4. 초대 링크 재발급
5. Vercel/Neon/GitHub 권한 회수
6. AuditLog와 보안 대시보드 기록 보존
