# 수동 리허설 절차

자동 E2E가 실제 운영 DB와 브라우저 흐름을 모두 대체하지 못하므로, 배포 전에는 아래 수동 리허설을 수행합니다.

## 1. 테스트 전 준비

- 운영 또는 리허설 PostgreSQL 준비
- migration 적용
- seed 실행
- OWNER 초대 URL 확보
- 테스트용 전화번호와 이메일 준비

## 2. 테스트 계정 구성

- OWNER: 권예찬 / 대표 / OWNER
- LEAD: 테스트리드 / 리드 / LEAD / 테스트팀
- MANAGER: 테스트매니저 / 매니저 / MANAGER / 테스트팀

## 3. OWNER 가입 테스트

OWNER 초대 URL로 가입하고 `/dashboard` 진입을 확인합니다.

## 4. OWNER 로그인 테스트

로그아웃 후 전화번호와 비밀번호로 다시 로그인합니다.

## 5. 조직 생성 테스트

OWNER가 테스트팀을 생성하고 팀 목록에서 확인합니다.

## 6. 직원 초대 테스트

OWNER가 테스트리드와 테스트매니저를 초대하고 초대 링크가 표시되는지 확인합니다.

## 7. 직원 가입 테스트

각 직원이 초대 링크로 가입하고 로그인할 수 있는지 확인합니다.

## 8. 직원 휴가 요청 테스트

테스트매니저가 연차, 반차, 예비군/병가/경조사 중 하나를 요청합니다.

## 9. OWNER 승인 테스트

OWNER가 테스트매니저의 요청을 승인, 반려, 승인 취소까지 확인합니다.

## 10. LEAD 승인 테스트

테스트리드가 담당 팀 직원 요청을 승인할 수 있는지 확인합니다.

## 11. 권한 차단 테스트

- MANAGER의 `/organization` 접근 차단
- MANAGER의 `/leaves/approvals` 접근 차단
- LEAD의 `/admin/leaves/settings` 접근 차단
- LEAD의 `/admin/audit-logs` 접근 차단
- 비로그인 `/dashboard` 접근 차단

## 12. 감사 로그 테스트

OWNER가 감사 로그에서 초대, 가입, 팀 생성, 휴가 요청, 승인 기록을 확인합니다. 민감정보가 보이면 안 됩니다.
