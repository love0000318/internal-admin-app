# 휴가 승인 정책 가이드

## 목적

휴가 승인 정책은 휴가 유형별로 승인 방식과 승인자를 다르게 운영하기 위한 설정입니다. 1차 MVP의 OWNER/LEAD 승인 흐름은 유지하면서, 2차에서는 휴가 유형마다 자동 승인 또는 단일 승인 규칙을 연결할 수 있습니다.

## 승인 방식

- `NONE`: 요청 생성 즉시 자동 승인됩니다.
- `SINGLE`: 한 명의 승인자가 승인/반려/취소를 처리합니다.
- `SEQUENTIAL`: 순차 승인 확장을 위한 예약 값입니다. 현재 단계에서는 실제 다단계 승인 워크플로우를 제공하지 않습니다.

## 승인자 규칙

- `OWNER`: OWNER만 승인할 수 있습니다.
- `TEAM_LEAD`: 요청자의 담당 팀 또는 하위 팀을 관리하는 LEAD만 승인할 수 있습니다.
- `TEAM_LEAD_OR_OWNER`: 담당 LEAD 또는 OWNER가 승인할 수 있습니다.
- `CUSTOM_USER`: 지정된 승인자 또는 OWNER가 승인할 수 있습니다.

공통 원칙으로 요청자 본인은 자기 휴가를 직접 승인, 반려, 승인 취소할 수 없습니다.

## 반려/취소 사유

정책별로 반려 사유 필수 여부와 승인 취소 사유 필수 여부를 설정할 수 있습니다. 기본값은 둘 다 필수입니다.

## 증명자료 확인 후 승인

`증명자료 확인 후 승인` 옵션을 켜면 휴가 요청의 증명자료 상태가 `ACCEPTED`가 되기 전에는 승인할 수 없습니다. 승인 화면에서는 경고가 표시되고, server action 직접 호출도 `attachment-not-accepted` 오류로 차단됩니다.

이 옵션은 예비군, 병가, 건강검진처럼 증명자료 검수가 중요한 휴가 유형에 적용할 수 있습니다. 기본 정책은 기존 운영 호환성을 위해 꺼져 있습니다.

## 휴가 유형 연결

OWNER는 `/admin/leaves/approval-policies`에서 승인 정책을 생성한 뒤 휴가 유형에 연결합니다. 기존 기본 휴가 유형은 seed에서 `담당 리드 또는 OWNER` 정책에 연결됩니다.

정책 변경은 변경 이후 생성되는 휴가 요청부터 적용하는 것을 운영 원칙으로 합니다. 이미 진행 중인 요청은 생성 당시의 상태와 현재 연결 정책이 다를 수 있으므로 승인 상세에서 정책 정보를 확인합니다.

## 자동 승인

`NONE` 정책은 요청 생성 시 자동 승인됩니다. 자동 승인된 요청도 LeaveLedger, Notification, AuditLog에 기록됩니다.

## 현재 구현 범위

- 자동 승인
- 단일 승인
- OWNER / TEAM_LEAD / TEAM_LEAD_OR_OWNER / CUSTOM_USER 규칙
- 반려/취소 사유 필수 여부
- 증명자료 확인 후 승인 차단
- 휴가 유형별 정책 연결

## 후순위

- 실제 순차 승인 단계 관리
- 대리 승인자
- 승인 SLA와 에스컬레이션
- 휴가 취소 요청용 별도 승인 정책

## 휴가 시작일 경과 시 자동 확정

승인 정책에는 휴가 시작일이 도래했을 때 승인 대기 요청을 자동 확정할지 설정하는 항목이 있다.

- 사용 여부: `autoConfirmWhenStartDatePassed`
- 확정 시점: `autoConfirmTiming`
  - `ON_START_DATE`: 시작일 당일부터 확정
  - `AFTER_START_DATE`: 시작일 다음 날부터 확정

증명자료 확인 후 승인 필수 정책(`requireAttachmentAcceptedBeforeApproval`)이 켜져 있으면 증명자료가 `ACCEPTED`인 요청만 자동 확정한다.
