# 휴가 Import 실제 운영 반영 Runbook

## 핵심 원칙

- 업로드 즉시 자동 반영하지 않습니다.
- 미리보기와 validation을 통과한 batch만 반영합니다.
- 최종 반영에는 OWNER Step-up 재인증이 필요합니다.
- 실제 개인정보 엑셀 원본은 GitHub나 public 폴더에 저장하지 않습니다.
- 운영 DB에서 `migrate reset`은 절대 사용하지 않습니다.

## 권장 반영 순서

1. 휴가 사용 상세 내역 파일을 먼저 업로드합니다.
2. 상세 사용 내역을 LeaveRequest와 LeaveLedger로 반영합니다.
3. 월별 연차 사용 내역 파일을 업로드합니다.
4. 엑셀 잔여 연차와 시스템 잔여 연차를 비교합니다.
5. 차이가 있는 직원만 조정 반영합니다.

이 순서를 권장하는 이유는 상세 사용 내역을 먼저 반영해야 시스템 사용량이 계산되고, 그 이후 월별 잔여 연차와 비교해야 조정값이 정확해지기 때문입니다. 월별 잔여를 먼저 조정하면 상세 사용 내역 반영 후 잔여가 다시 달라질 수 있습니다.

## 1단계. OWNER 로그인

1. production URL에 접속합니다.
2. 총괄 관리자 계정으로 로그인합니다.
3. `/admin/security` 또는 보안 대시보드 접근이 정상인지 확인합니다.
4. AuditLog 화면 접근이 정상인지 확인합니다.

## 2단계. 업로드 화면 접속

1. `/admin/leaves/import`로 이동합니다.
2. OWNER 외 계정에서는 접근할 수 없어야 합니다.
3. 업로드 설명과 import 이력을 확인합니다.

## 3단계. 휴가 사용 상세 내역 업로드

1. 업로드 유형을 `휴가 사용 상세 내역` 또는 자동 감지로 선택합니다.
2. 상세 파일을 선택합니다.
3. 파싱 후 batch 상세 화면으로 이동합니다.
4. header row가 정상 감지되었는지 확인합니다.
5. 날짜 변환 결과를 확인합니다.
6. 직원 매칭 결과를 확인합니다.
7. 휴가 유형 매핑 결과를 확인합니다.
8. 상태 매핑 결과를 확인합니다.
9. UNKNOWN 상태 row가 없는지 확인합니다.
10. 중복 의심 row를 확인합니다.
11. 휴가취소 row가 `취소 제외`로 표시되는지 확인합니다.
12. 승인대기 row가 pending으로 반영 예정인지 확인합니다.
13. 승인완료 row가 used로 반영 예정인지 확인합니다.
14. 오류 row가 있으면 반영하지 않습니다.

## 4단계. Step-up 재인증

1. 최종 반영 버튼을 클릭합니다.
2. Step-up 재인증이 필요하다는 메시지가 나오면 보안 확인 화면에서 비밀번호를 다시 입력합니다.
3. Step-up 성공 후 batch 상세 화면에서 다시 최종 반영을 실행합니다.

## 5단계. 상세 파일 최종 반영

1. 반영 예정 직원 수를 확인합니다.
2. 생성 또는 연결될 LeaveRequest 수를 확인합니다.
3. 생성될 LeaveLedger 수를 확인합니다.
4. 제외/경고 row 수를 확인합니다.
5. 최종 반영을 실행합니다.
6. 반영 완료 row 수, 생성된 LeaveRequest 수, 생성된 LeaveLedger 수, skip row 수를 확인합니다.
7. 같은 batch를 다시 반영하려고 하면 차단되어야 합니다.

## 6단계. 월별 연차 사용 내역 업로드

1. 상세 파일 반영이 끝난 뒤 월별 파일을 업로드합니다.
2. 업로드 유형을 `월별 연차 사용 내역` 또는 자동 감지로 선택합니다.
3. 직원 매칭 결과를 확인합니다.
4. 입사일 파싱 결과를 확인합니다.
5. 엑셀 잔여 연차와 시스템 잔여 연차를 비교합니다.
6. 차이값을 확인합니다.
7. 차이가 0인 row가 조정 대상에서 제외되는지 확인합니다.
8. 차이가 있는 직원만 조정 예정인지 확인합니다.
9. 오류 row가 있으면 반영하지 않습니다.

## 7단계. 월별 파일 최종 반영

1. Step-up 재인증 상태가 유효한지 확인합니다.
2. 연차 조정 예정 수를 확인합니다.
3. 최종 반영을 실행합니다.
4. 생성된 LeaveAdjustment와 LeaveLedger ADJUSTED 수를 확인합니다.
5. 직원별 잔여 연차 재검증 결과를 확인합니다.

## 8단계. 반영 후 검증

1. 구성원 휴가 현황 화면에서 직원별 잔여 연차를 확인합니다.
2. `/leaves/me`에서 직원 본인 화면의 잔여 수량도 확인합니다.
3. LeaveLedger 리포트 또는 상세에서 import source를 확인합니다.
4. AuditLog에서 import upload, validation, apply 기록을 확인합니다.
5. 취소 row가 사용량으로 차감되지 않았는지 확인합니다.
6. 승인대기 row가 used가 아니라 pending으로 반영되었는지 확인합니다.

## UNKNOWN row 처리

- 자동 반영하지 않습니다.
- OWNER가 상태를 직접 매핑해야 합니다.
- 상태가 명확하지 않으면 반영하지 않고 제외합니다.

## 미매칭 row 처리

- 자동 반영하지 않습니다.
- OWNER가 수동 매칭해야 합니다.
- 수동 매칭 전에는 최종 반영할 수 없습니다.

## 중복 의심 row 처리

- 동일 직원, 동일 시작일, 동일 종료일, 동일 휴가 유형, 동일 사용일수의 기존 기록이 있으면 중복 의심입니다.
- 기본적으로 skip 또는 확인 필요 상태로 처리합니다.
- 중복이 아니라고 판단되면 원본 파일과 시스템 기록을 다시 확인한 뒤 별도 운영 판단으로 처리합니다.

## 휴가취소 row 처리

- 사용량으로 차감하지 않습니다.
- LeaveLedger USED를 생성하지 않습니다.
- 필요 시 취소 이력으로만 확인합니다.

## 승인대기 row 처리

- used가 아니라 pending으로 반영합니다.
- 승인 완료 사용량과 혼동하지 않도록 반영 후 직원별 pending 수량을 확인합니다.
