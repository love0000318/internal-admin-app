# OWNER 운영 체크리스트

이 문서는 OWNER와 운영 관리자가 직원 오픈 후 반복적으로 확인해야 할 운영 절차를 정리한다. 실제 secret, token, DB URL은 문서나 메신저에 기록하지 않는다.

## 직원 초대

1. `/organization/invitations` 또는 직원 관리 화면에서 초대를 생성한다.
2. 생성 직후 표시되는 단축 초대 URL과 1회용 가입 인증 코드를 확인한다.
3. 직원에게 초대 URL과 가입 인증 코드를 안전한 채널로 함께 전달한다.
4. 초대 코드가 분실되면 기존 초대를 재발급한다. 기존 링크와 코드는 더 이상 사용할 수 없다.

주의:

- 초대 링크와 인증 코드를 공개 채널에 공유하지 않는다.
- 인증 코드는 생성 직후 한 번만 표시된다.
- 초대 재발급은 보안상 고위험 작업이므로 Step-up 재인증이 필요할 수 있다.

## 직원 가입 확인

- 직원 상태가 ACTIVE인지 확인한다.
- 이름, 팀, 직급, 역할이 맞는지 확인한다.
- 잘못 가입된 계정은 즉시 비활성화하고 AuditLog를 확인한다.

## 휴가 승인

1. `/leaves/approvals`에서 승인 대기 요청을 확인한다.
2. 요청자, 휴가 유형, 기간, 반차 여부, 증명자료 상태를 확인한다.
3. 승인 또는 반려한다.
4. 승인 후 직원의 잔여 수량과 AuditLog가 정상 갱신되었는지 확인한다.

## 근태 확인

근태 기능을 운영 범위에 포함한 경우:

- `/admin/attendance`에서 직원별 출근/퇴근 상태를 확인한다.
- 중복 출근, 누락 퇴근, 수정 요청을 검토한다.
- 근태 메뉴가 존재하지 않으면 이번 릴리즈에서 근태가 제외된 상태로 간주한다.

## 직원 비활성화

- 퇴사자 또는 사용 중지 대상만 비활성화한다.
- 마지막 OWNER는 비활성화할 수 없다.
- 자기 자신을 비활성화하지 않는다.
- 비활성화는 Step-up 재인증이 필요하다.
- 비활성화 후 해당 직원의 세션이 revoke되었는지 확인한다.

## 비활성 직원 삭제/익명화

- ACTIVE 직원은 삭제할 수 없다.
- 비활성 직원만 영구 삭제 또는 익명화 대상이다.
- 휴가/근태/AuditLog 기록이 있는 직원은 업무 기록 보존을 위해 개인정보 익명화 삭제로 처리한다.
- 삭제/익명화는 되돌리기 어렵기 때문에 영향 분석과 Step-up 재인증 후 수행한다.
- AuditLog는 삭제하지 않는다.

## AuditLog 확인

- OWNER 권한 변경
- 직원 비활성화
- 직원 삭제/익명화
- 초대 재발급
- CSV export
- 로그인 차단
- 비인가 접근 차단
- Step-up 실패

위 이벤트는 정기적으로 확인한다.

## 보안 대시보드 확인

`/admin/security`에서 최근 고위험 이벤트, 로그인 실패, 초대 재발급, CSV export, Job 실패를 확인한다.

## Step-up 재인증이 필요한 작업

- OWNER 권한 부여/제거
- 직원 role 변경
- 직원 비활성화
- 비활성 직원 영구 삭제/익명화
- 초대 재발급
- CSV export
- AuditLog export
- 세션 강제 revoke, 구현된 경우
- 보안/정책 변경, 적용된 경우

## 절대 하면 안 되는 것

- 운영 DB에서 `prisma migrate reset` 실행 금지
- 초대 링크/인증 코드를 공개 채널에 공유 금지
- Vercel/Neon secret을 문서나 메신저에 공유 금지
- OWNER 계정을 여러 사람이 같이 사용 금지
- 마지막 OWNER를 비활성화하거나 삭제 시도 금지
- tokenHash/codeHash/passwordHash를 화면, CSV, AuditLog에 노출 금지
- 민감정보가 포함된 screenshot을 공개 채널에 공유 금지
